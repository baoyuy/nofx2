# 收益保护整改：本地验收与发布说明

当前仅在本地部署；服务器部署待用户批准。目标交易员是 binance_paper 普通 AI 交易模式。原有带单方向研究改动保留。

## 行为变化

- 盈亏比按实际参考报价与成交价、止盈止损距离及往返成本计算；原先推导入场价的伪校验已删除。
- 多空统一使用主周期 ATR，调整止损后重新计算净盈亏比及仓位。
- 单笔止损风险默认权益1%，组合止损风险4%，UTC日亏损3%、历史峰值回撤10%后暂停新增风险。保证金与可用余额分别限制；旧策略未配置预算时也使用这些默认值。
- 持仓若缺少可验证、数量完整的止损，拒绝继续增加风险。下单后先设置保护单，再确认成交并复核风险；不合格则走紧急平仓验证。
- ROI与峰值ROI使用开仓成本保证金；当前保证金占用独立按市值计算。R使用成交价到初始止损的标的价格距离，持久化且不随止损收紧改变。
- 可选R保护在纸账户独立运行；保本与追踪一经触发不会解除或放宽。监控沿用每分钟周期，AI故障不停止监控。
- 币池失败、删除、全部过期时停止新增；开仓前再次读池，free方向也不能交易池外币。默认crypto和follow，可配置资产范围、允许列表、自主方向。退出由持仓管理独立处理。
- 两层提示词明确评分/交易职责；无结构化AI回复计为失败。模型响应后刷新报价，仍校验指标时效和执行报价。

## 本地访问与验收

界面：http://127.0.0.1:13000；API：http://127.0.0.1:18080。使用独立空SQLite和新生成密钥，只监听本机。健康检查、前端代理、空交易员列表、浏览器页面与风险策略API保存读回通过。

重建：`go build -o /tmp/nofx-risk-local/nofx .`；前端在web目录执行`npm run build`。
启动：`python3 scripts/local-risk-preview.py`。脚本打印本次隔离数据和日志目录；停止使用Ctrl-C。每次启动建立新隔离目录，避免恢复运行中的交易员。

保守模拟配置见`paper-risk-profile.json`（POST /api/strategies请求体，不是JSONC编辑器文件）。已通过本地API保存验证：3倍杠杆、最多3仓、保证金35%、单笔风险0.7%、组合2.5%、日亏损2%、峰值回撤8%、成本预算0.2%、净盈亏比2、信心75、ATR1.5—4、1R保本、2R追踪、峰值回吐30%。这些是待模拟验证的初始预算，不代表最优参数或收益承诺。固定BTC/ETH/SOL用于先隔离执行效果；后续可切换受限动态池。

## 使用边界

- 可配置R/价格收益保护仅支持binance_paper；实盘交易所继续拒绝开启。没有通过删除校验来假装支持原生止损更新。实盘扩展需要逐交易所验证单向/双向仓位、止损替换、数量精度和失败补偿。
- 启用保护只适用于此后新开的仓位；旧仓无初始R，不推测、不追溯套用新规则。旧仓保留原保护行为，看板标明资格。
- 日亏损/回撤是限制新增风险，不是自动全账户强平。UTC跨日只重置日基线，历史峰值不重置；回撤暂停要等权益回到预算内，不能靠重启清除。
- 权益基线按交易员持久化。入金/出金及多个交易员共享账户尚无现金流归因，不应把这些情况下的百分比当作纯交易收益。发布到当前纸账户时保持独立账户和稳定本金；实盘共享账户需独立账户级风险协调与资金流校正后再用。
- 成本是预算，不是成交保证；跳空、延迟、断网和交易所故障可能穿越止损。每分钟采样也不能捕获所有盘中峰值。
- 没有增加分批平仓或修改止损的AI动作。当前执行协议只支持开/全平/hold/wait，保护由程序执行。
- 网格、镜像和Vergex方向状态机保持各自执行机制；普通AI风险预算不宣称覆盖这些独立模式的全部交易路径。

## 批次审查与验证

1. 下单入口：真实净盈亏比、风险预算、成交后校验；审查并修正止损覆盖数量和收益分母。
2. 初始R与保护：重启持久化、单调止损、资格与状态展示；多空反转机制验证。
3. 币池/配置/提示词：删除过时快照回退要求；预算、ATR和R配置JSONC往返测试。
4. 运行链路：原生保护先行、异常回复计失败、账户暂停可观测、模型延迟报价刷新；补充实际开仓准备与成交检查模拟。
5. 本地验收：完整Go测试通过；前端76个文件637项测试通过；TypeScript和生产构建通过。前端仍有打包体积提示和测试环境TimeoutNaN提示，无失败。

反转场景测试模拟10倍杠杆峰值ROI28.69%即标的2.869%后回落：初始价格风险1%、1R保本/2R追踪时保护可触发，旧5%价格阈值不触发。它验证机制，不是该交易员真实逐笔回放，不能用来宣称实际收益率。

## 批准后服务器发布顺序

1. 先核对运行版本与目标交易员，备份数据库、配置和当前可回滚程序；不在日志/仓库复制密钥。
2. 记录持仓和原生保护订单状态，检查新预算是否会暂停开仓，以及现有仓位是否缺止损。
3. 发布程序与前端；迁移新增账户风险/初始R状态。不要用本地空数据库覆盖服务器数据库。
4. 单独确认并应用目标纸账户策略；新预算对旧策略立即生效，R保护对新仓生效。不要把启用R当作给旧仓补保护。
5. 检查健康、策略保存/读回、暂停原因、持仓保护状态及一次完整决策；先观察模拟运行，再评价交易表现。

回滚：停止本次实例，恢复备份程序/前端及对应配置；数据库优先保留兼容新增字段，若必须恢复数据库则先备份当前状态并核对交易所真实持仓，防止旧快照与持仓生命周期错配。回滚不能撤销已经发生的成交。服务器部署、停止运行交易员或改动其关键参数须用户批准后执行。
